# Тихая установка Official Tailscale

Запускать через локальный SSH с TTY: установщик перезапускает Tailscale. Это новый вариант для выделенного тестового роутера; резервные копии не создаются по требованию пользователя.

```sh
wget -O /tmp/tailscale-quiet.sh 'https://raw.githubusercontent.com/TMN88/TS_client_install/feat/quiet-official-https/tailscale-router-quiet.sh' &&
sh /tmp/tailscale-quiet.sh
```

Auth key вводится один раз в скрытом запросе терминала. Ключ не включается в команду, окружение и файл: builtin printf передаёт его клиенту через pipe и `--auth-key=file:/dev/stdin`. Сообщения об ошибках очищаются от строк tskey-auth. Проверка свойств/срока ключа выполняется сервером.

До первого входа задаётся `TS_FORCE_NOISE_443=true`. Для входа установлен предел 90 секунд, слепой цикл перерегистраций отсутствует. При Running используется сохранённая регистрация без запроса ключа. Обычные установщики не изменены.

Если внешний установщик вернул ошибку после фактической установки пакета, дальнейшая настройка допускается только при наличии работающей команды version, tailscaled и исполняемого init. После применения userspace-настроек обязательно проверяются ответ демона, Running, IP, state-файл и автозапуск. Этот путь устраняет остановку до применения собственных параметров, но не объявляет произвольную ошибку внешнего установщика успехом.

Реальный тест 04.11.2026: Cudy WR3000S v1, OpenWrt 25.12.5, Tailscale 1.104.5 OpenWrt-UPX. Авторизация по пользовательскому ключу через HTTPS/443 прошла с первой отправки. Повторные запуски не запрашивали ключ. После reboot сохранились ID и адрес узла; SSH по Tailscale IPv4 проверен с ПК. Домашний роутер не изменялся. До этого первоначальный вызов внешнего установщика установил пакет, но завершился ошибкой старта стандартной службы; исходный тихий AUTO остановился до запроса ключа. Финальный скрипт проверен на уже установленном после этой ошибки пакете; полностью пустая установка нового файла отдельным заводским сбросом ещё не повторялась.

В исходной браузерной схеме при прямом пути через домашний шлюз авторизация принималась, но зависало получение netmap. HTTPS/443 оказался рабочим вариантом; однозначная первопричина сбоев на порту 80 и гарантия успешности на любом роутере не заявляются. Административный флаг non-ephemeral отдельно не прочитан. Ключ после испытаний следует отозвать.
