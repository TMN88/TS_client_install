# Tailscale на клиентском OpenWrt: вход через браузер

Установщик использует userspace-режим и постоянный файл идентичности. Авторизация выполняется по ссылке через браузер, без Auth key. В скрипте нет режима удаления или сброса регистрации. Повторный запуск сохраняет существующую идентичность, поэтому уже зарегистрированное Ephemeral-устройство сам по себе не исправляет.

## Установка через wget

В SSH-консоли роутера выполните:

```sh
wget -O /tmp/tailscale-router-install.sh 'https://raw.githubusercontent.com/TMN88/TS_client_install/main/tailscale-router-install.sh' &&
sh /tmp/tailscale-router-install.sh
```

На новом устройстве скрипт покажет ссылку `https://login.tailscale.com/...`. Откройте её на компьютере или телефоне, войдите в нужный аккаунт Tailscale и подтвердите подключение роутера. Не отправляйте эту ссылку посторонним. Установщик ждёт до 5 минут. Если время истекло, завершите вход и повторите запуск. Код выхода 2 означает, что установка сохранена, но подключение не подтверждено.

Существующие файлы Auth key и переменные `TS_AUTHKEY`, `TS_AUTH_KEY`, `TS_AUTHKEY_FILE` при авторизации не используются. Подключение через браузер не создаёт Ephemeral-узел. В консоли Tailscale убедитесь, что у нового устройства нет метки Ephemeral.

## Что настраивается

- Пакет устанавливается через `apk` или `opkg`, если отсутствует. Прошивка не обновляется.
- Сохраняются UCI-настройки и путь к state-файлу. DNS, принятие маршрутов и управление netfilter отключаются, как в исходном скрипте.
- SOCKS5 по умолчанию доступен только на `127.0.0.1:1055`. Отключение: `SOCKS5_LISTEN='' sh /tmp/tailscale-router-install.sh`. Доступ с LAN, если он нужен: `SOCKS5_LISTEN=0.0.0.0:1055 sh /tmp/tailscale-router-install.sh`; доступ к такому прокси ограничьте firewall.
- Правка init-скрипта повторяема: известные дубли аргументов удаляются, неподдерживаемый формат вызывает остановку.
- Сохранён намеренный перезапуск при поднятии WAN/WAN6, необходимый для восстановления подключения на этих роутерах. Задержка 5 секунд объединяет близкие события WAN и WAN6 в один перезапуск.
- Ошибки демона доступны через `logread -e tailscale`. Отправка диагностических логов Tailscale отключена.
- Установщик проверяет ответ демона, режим userspace и состояние Running. После обновления пакета Tailscale может потребоваться повторное применение установщика и проверка доступа.

## Резервная копия и откат

Перед изменением файлов установщик сохраняет резервную копию и печатает команду отката вида:

```sh
sh /etc/tailscale/installer-backups/backup-XXXXXX/rollback.sh
```

Используйте реальный путь из вывода. Копия включает прежние конфигурационные файлы и, если он существовал, `identity.state` с секретами узла. Не публикуйте эти файлы. Откат восстанавливает конфигурацию и прежний режим запуска службы, сохраняя текущую идентичность и установленный пакет. Ошибка применения конфигурации или запуска демона вызывает попытку отката. Ошибка входа через браузер сохраняет установку для завершения авторизации.

## Проверка доступа

Запускайте установку при наличии локального доступа: перезапуск Tailscale временно обрывает соединение через него. С другого устройства той же tailnet проверьте реальный SSH-вход на показанный адрес, например `ssh root@100.x.y.z`, либо доступ к LuCI. Нужны разрешения tailnet и служба, доступная через localhost. Встроенный Tailscale SSH не включается; доступ ко всей LAN и роль exit node не настраиваются.

После обычной браузерной регистрации проверьте отсутствие метки Ephemeral и повторный SSH-вход после перезагрузки роутера. Версия с браузерным входом пока не проверена на реальном роутере. На Windows сохраняйте `.sh` с окончаниями LF, без BOM; предоставленный файл уже имеет такой формат.
