# Установка Tailscale на клиентский OpenWrt

Скрипт `tailscale-router-install.sh` сохраняет userspace-режим исходного скрипта. Прошивку не обновляет. Пакет устанавливает через `apk` или `opkg`, только если отсутствует `tailscale` или `tailscaled`. Запускайте сначала на одном роутере, имея локальный доступ: перезапуск Tailscale временно обрывает соединение через него.

## Запуск

Передайте файл на роутер в `/tmp/tailscale-router-install.sh`, затем в SSH-консоли роутера выполните:

```sh
sh /tmp/tailscale-router-install.sh
```

На новом устройстве можно авторизоваться автоматически через Auth key, как описано ниже. Без ключа скрипт покажет ссылку авторизации. Ожидание ограничено 60 секундами. Если не успели, завершите авторизацию и повторите запуск. Код выхода 2 означает, что конфигурация установлена, но подключение не подтверждено.

## Автоматическая авторизация

Создайте Auth key в [настройках Tailscale](https://login.tailscale.com/admin/settings/keys). Для одного роутера подойдёт одноразовый ключ; для установки на нескольких нужен Reusable либо отдельный ключ для каждого устройства. Отключите Ephemeral для постоянного клиентского роутера. Если в tailnet требуется ручное одобрение устройств, используйте Pre-approved с нужными правами администратора или одобрите устройство отдельно. Срок действия Auth key и срок действия ключа самого устройства — разные настройки.

Передайте ключ отдельно от репозитория, создав на роутере файл `/tmp/tailscale-authkey` с правами `600`, содержащий только ключ. Для ручной подготовки файла в SSH-консоли:

```sh
umask 077
cat > /tmp/tailscale-authkey
```

Вставьте ключ, нажмите Enter, затем Ctrl+D. Это подготовка секрета; дальнейшая регистрация выполняется без браузера:

```sh
sh /tmp/tailscale-router-install.sh
```

Система автоматической настройки роутеров может заранее передать тот же файл без ручного ввода. Другой путь задаётся так:

```sh
TS_AUTHKEY_FILE=/tmp/my-tailscale-key sh /tmp/tailscale-router-install.sh
```

Ключ передаётся Tailscale через `--auth-key=file:...`, без его значения в аргументах процесса. Временная внутренняя копия удаляется при завершении установщика. Исходный файл сохраняется для повторной попытки; после успешного подключения удалите его: `rm -f /tmp/tailscale-authkey`. Каталог `/tmp` также очищается при перезагрузке. Идентичность подключённого узла хранится отдельно в постоянном state-файле, поэтому для обычной перезагрузки Auth key не требуется. На уже подключённом узле повторная регистрация не выполняется.

Не добавляйте настоящий ключ в скрипт, README, issue или GitHub. Автоматическая авторизация реализована, но сам ключ в поставку не включён.

На Windows сохраняйте `.sh` с окончаниями строк LF, без BOM. Предоставленный файл уже имеет такой формат.

## Изменения

- SOCKS5 по умолчанию слушает `127.0.0.1:1055`. Если клиенты LAN использовали прежний прокси на адресе роутера, это изменит их доступ. Чтобы осознанно сохранить прежнее поведение, задайте `SOCKS5_LISTEN=0.0.0.0:1055 sh /tmp/tailscale-router-install.sh`. Доступ к такому прокси ограничьте firewall. Для отключения прокси задайте `SOCKS5_LISTEN=''`.
- Сохраняются существующие UCI-настройки и путь к файлу идентичности. DNS и принятие маршрутов выключаются, как в исходнике. На уже подключённом узле применяется `tailscale set`, сохраняющий остальные настройки.
- Настройка параметров службы повторяема: известные аргументы заменяются, дубликаты удаляются. При неизвестном формате init-скрипта работа останавливается до изменения конфигурации. Обновление пакета Tailscale в будущем может заменить init-скрипт: после обновления повторно запустите установщик и проверьте доступ.
- Принудительный перезапуск при поднятии WAN/WAN6 сохранён как намеренный обход наблюдавшейся проблемы с подключением, в том числе после перезагрузки. Hook ждёт 5 секунд; события WAN и WAN6 в этом интервале объединяются в один перезапуск. Обработка остальных hotplug-событий не блокируется. Посторонний hook с тем же именем вызывает остановку для ручного разбора.
- Локальные ошибки демона остаются доступны через `logread -e tailscale`; отправка диагностических логов Tailscale выключена.
- Ошибки применения файлов и запуска демона вызывают попытку восстановления прежней конфигурации. Ошибка авторизации после успешного запуска сохраняет новую конфигурацию для завершения входа.

## Резервная копия и откат

Скрипт печатает путь к резервной копии и команду вида:

```sh
sh /etc/tailscale/installer-backups/backup-XXXXXX/rollback.sh
```

Используйте реальный путь из вывода. Копия содержит старые конфигурационные файлы и, если он существовал, файл идентичности `identity.state`. Он содержит секреты узла: не публикуйте и не пересылайте его. Откат восстанавливает файлы, автозапуск и прежнее состояние запуска службы; пакет не удаляет и текущую идентичность автоматически не заменяет. Каталог резервных копий со временем занимает flash — удаляйте ненужные копии вручную только после проверки доступа.

## Проверка результата

Установщик проверяет ответ демона, аргумент userspace и состояние `Running`. Это не доказывает возможность удалённого входа. С другого устройства в той же tailnet проверьте реальный вход по обычному SSH на показанный Tailscale IPv4, например `ssh root@100.x.y.z`, либо откройте LuCI. Нужны разрешения tailnet и служба, доступная на localhost роутера. Встроенный Tailscale SSH скрипт не включает. Доступ ко всей LAN за роутером и роль exit node скрипт не настраивает; существующие объявления маршрутов на подключённом узле сохраняет.

Безопасный пробный запуск — на одном роутере, с сохранённой локальной сессией; затем проверка удалённого SSH и работы после перезагрузки. На реальном роутере эта версия пока не проверялась.
