# TS mini AUTO для OpenWrt

Отдельный вариант TS mini с авторизацией через заранее созданный auth key официального Tailscale. Существующие установщики не меняются.

После слияния PR:

```sh
wget -O /tmp/TS_client_install_auto.sh 'https://raw.githubusercontent.com/TMN88/TS_client_install/main/TS_client_install_auto.sh' &&
sh /tmp/TS_client_install_auto.sh
```

Запускайте от root через интерактивный SSH. Заранее создайте auth key в https://login.tailscale.com/admin/settings/keys (рекомендуется одноразовый, с минимальным сроком действия, без Ephemeral для постоянного клиента). Вставьте его в скрытое приглашение и нажмите Enter. Браузерная авторизация на роутере не нужна. Политика сети может требовать отдельного одобрения устройства.

Скрипт сохраняет схему mini: GuNanOvO persistent install при отсутствии бинарников, userspace networking, SOCKS5 `0.0.0.0:1055`, отключённые DNS/приём маршрутов/netfilter, постоянный state и hotplug WAN/WAN6. SOCKS5 доступен на всех интерфейсах: ограничьте доступ доверенной сетью правилами firewall. Готовое подключение не требует нового ключа. Перед изменениями создаётся резервная копия конфигурации `/etc/tailscale/auto-backup-*`; состояние и ключи устройства не удаляются. Автоматического отката нет: после ошибки смотрите указанную резервную копию.

Загрузчик GuNanOvO закреплён на commit `7a0e4bb0f025fe33a7731ac0130d2fbc34734fb5` с проверкой SHA-256. Сам загрузчик использует обновляемый feed для пакетов; весь downstream не закреплён этим хешем. Если бинарники уже есть, обновление пакета пропускается. Поддерживается init с ожидаемой строкой `procd_append_param command --state "$state_file"`; другой формат приводит к остановке.

Ключ читается из `/dev/tty` без эха, не принимается в аргументах или переменных окружения, не выводится в диагностику. Временный файл имеет права 600 внутри каталога 700 на `/tmp` (tmpfs); в Tailscale передаётся только `--auth-key=file:...`. После завершения авторизации файл удаляется, при EXIT/HUP/INT/TERM восстанавливается терминал и убираются временные файлы. Xtrace/verbose отключены до ввода; core dump запрещён. SIGKILL/потерю питания перехватить нельзя: остатки в tmpfs исчезнут после перезагрузки. Root и средства записи SSH-сеанса остаются за пределами этой защиты; не вводите ключ в записываемой сессии. Сам Tailscale хранит собственные ключи устройства в постоянном state — это необходимо для повторного подключения.

Сторонний control server автоматически не переключается. При ошибке существующих нестандартных Tailscale prefs скрипт не использует `--reset` и не сбрасывает их. Успех требует работающих бинарников, состояния Running, IPv4 диапазона 100.64.0.0/10, процесса tailscaled, автозапуска и непустого state. Это не подтверждает доступность клиента из другой сети или восстановление после перезагрузки.

Проверки: `sh -n TS_client_install_auto.sh`, `shellcheck -s sh TS_client_install_auto.sh`, `python3 -m unittest discover -s tests -v`. Тесты изолированы и используют имитации команд; реальный роутер и реальный ключ не используются. Для отключения ANSI-цветов: `NO_COLOR=1 sh TS_client_install_auto.sh`.

Основание безопасной передачи ключа: https://tailscale.com/docs/reference/tailscale-cli/up и https://tailscale.com/docs/features/access-control/auth-keys/how-to/secure-auth-keys.
